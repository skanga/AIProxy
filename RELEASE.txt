AIProxyOauth 4.2
===============

Discover provider-reported model limits and capabilities, and export client
configuration for Codex and pi.

Changes:
- Extend the OpenAI-compatible /v1/models response with OpenRouter-style
  context/output limits, names, input modalities, and supported parameters.
- Add aiproxy metadata for provider-qualified IDs, source, fetch time,
  reported capabilities, reasoning efforts, endpoints, and Codex auth profile.
- Retain Codex catalog metadata alongside cached model IDs and account filters.
- Read Anthropic limits from the catalog instead of assuming 200K context.
- Omit unknown limits and validate optional metadata without exposing raw
  upstream catalog objects or model instructions.
- Preserve native Anthropic model responses for Claude Code.
- Add scripts/export-client-config.py (Python 3.11+) for Codex TOML and pi
  models.json snippets. Keep credentials in environment variables.
- Run all offline Python tooling tests in the release workflow.

Compatibility:
- Existing OpenAI model fields, IDs, routing, and explicit overrides remain.
- Extra model fields are extensions; clients may need explicit configuration.
- The exporter requires verified overrides for missing required token limits.
- pi's standard adapter cannot use native Codex auth because it sends output
  limits that the native profile rejects. Use another supported route.
- Claude Code's native model picker still does not list Copilot models;
  use explicit Copilot IDs advertising /v1/messages.
- Live client behavior and live account metadata were not verified.

Validation:
- 620 Java tests and 33 offline Python tests pass.
- Fat JAR builds with Java 21; version command reports AIProxyOauth 4.2.

Requires Java 21 and an account with access to the selected provider/model.
See README.md for model metadata and client configuration instructions.

Download AIProxyOauth-4.2.jar and run:
  java -jar AIProxyOauth-4.2.jar --help
